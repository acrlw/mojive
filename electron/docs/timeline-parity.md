# Timeline behavior and source mapping

The Electron editor retains three independent tracks. Keyframes and snapshots store scene poses; takes store sampled poses over time. This is a local kinematic editor and recorder. It does not create simulation states, velocities, actuator dynamics, or MuJoCo physics playback.

A pose contains every scene node's position, quaternion, and scale, scalar joint values, authored joint origins, and ball/free joint configurations. It is not a second copy of the complete project: changing materials, scene topology, visibility, or assets is outside pose capture. Load checks complete object/joint compatibility before changing the scene.

Presets are not automatically interpolated when scrubbing. Playback requires a recorded take.

## Presentation and ownership

`Timeline.tsx` owns transient selection, range gestures, marker previews, menu state and view navigation. App owns document transactions, pose loading, recording, playback and export. A marker drag does not reorder/mutate document keys before release: reordering the captured DOM element during a gesture can lose pointer ownership and cancel the transaction.

Every timeline toolbar function is exposed directly in one horizontal row: transport/current time, Record and its adjacent Export/Stop action, snapshot and keyframe capture, previous/next key navigation, Speed, Zoom/Fit, all three Follow modes, and context-sensitive View/Loop endpoints. Fit stays adjacent to Zoom. There is no generic More/settings or range-summary popover. Export retains the same target beside Record when it becomes Stop; starting export scrolls that target into view.

When the complete toolbar budget does not fit, the main controls scroll horizontally instead of wrapping or hiding operations. Follow remains in the visible fixed tail at every supported width. At 480 logical pixels and above, both range fields remain fixed beside it; below that width the fields join the scrolling controls, where each complete editor remains reachable. Compact icons preserve semantic titles and accessible names. The range scope uses a short View/Loop caption, or its semantic icon in narrow layouts. No value change chooses a different layout.

Recording continues until manual Stop. There is no End control, initial-window stop, fixed duration/frame-count limit, or reset to zero when the cursor crosses the previous content boundary. The persisted `duration` is only a finite content extent for authoring and serialization. Recording, seeking and keyframe edits extend it as needed; view navigation never changes it; timestamp validation still requires finite nonnegative values and a saved extent covering authored content. Take loops remain independent actual-sample ranges. This matches the native separation of `manual_view_range` from recorded frame indices in `python/ui/workspace/timeline_panel.py::_draw_range`.

Projection uses `88 × zoom` pixels per second independently of content extent. Growing content cannot rescale the ruler or move a marker in an unchanged view. Follow translates the window without extending content. Stopping recording retains the resulting view. Undo restores authored content without shrinking the extent needed by the retained cursor, so subsequent keyframes and snapshots remain valid for save/reopen. Chronological take rendering uses a lower-bound search and visits only visible samples, rather than rescanning the recording's full history on every frame.

`timelineNavigation.ts` follows `python/interaction/timeline.py`: interactive zoom spans range from 0.001 seconds to `max(60, 4 × content span)`, with floating-point precision protection and deliberate manual ranges included in the context. These are navigation bounds, never recording limits. Browser pixel, line and page wheel deltas are normalized before the native exponential response, with small trackpad deltas retained and individual extreme deltas bounded. The pointer time remains at the same screen position; locked Follow uses the playhead anchor. Signed view starts permit context before zero while authored timestamps remain nonnegative. Pan and zoom cannot recursively grow their own limits.

The track renders at viewport width from the precise view range. A bounded scrollbar proxy controls pan without feeding its rounded pixel position back into wheel zoom. This avoids browser canvas-size limits and fractional-scroll drift at high zoom. Wheel ownership is limited to the track, leaving lane labels and numeric editors independent.

The three 44-point tracks retain one scroll owner and one-pixel lane borders. The label column is exactly 160 points high: a 28-point ruler/header plus three tracks. It does not stretch a painted label block below the final lane. Metadata details appear only for an actual keyframe/snapshot selection or selected keyframes; an empty or merely active Take has no footer. New/Clear/Delete Take and selected-frame loop/delete actions remain in the Take header/track context menu, with the original transaction ownership and shortcuts. Follow choices divide one zero-padding, zero-gap surface with square internal corners. Shared MiSans, JetBrains Mono, theme tokens and ordinary circular corners are reused.

All toolbar commands, numeric fields and follow cells share the native 28-point height; icons use the adopted 20-point canvas. Focused toolbar controls own local keyboard events so Delete does not act on selected keys behind a focused Follow button; global Undo/Redo, Open, Save and Settings shortcuts still reach App. The production playhead is sourced from `python/ui/workspace/timeline_track.py::_playhead`: an opaque 8-by-9-point head, a one-point line beginning six points below the ruler top, and line alpha 0.85. Both resolve `theme.danger` (`#D06744` in Dark and `#AF452E` in Light from `python/design/resources/themes.json`), independently of sage keyframe/selection colors.

Time/range fields reserve eight numeric characters plus 32 points for input and unit insets. Idle captions retain three decimals while they fit, then reduce decimals or use complete scientific notation within the same eight-character budget. This never rounds stored data: double-click or Tab opens full-precision input. Zoom reserves six characters plus the same insets (`8000.0%`). These widths derive from the resolved numeric font. Narrow panels retain the field budgets and use horizontal scrolling instead of adding rows, narrowing fields or hiding controls. The head belongs to the sticky ruler so scrolling cannot hide it behind the ruler's opaque surface; the line paints above the ruler at layer 5, below the sticky label column at 6.

## Verification

Run `make timeline-review` from `electron`; `make timeline-wheel-review` is the production Electron acceptance target for wheel navigation. Use both targets to check the navigation contract. `tests/timeline-navigation.test.mjs` checks wheel units, cursor anchoring, signed context, bounded pan/zoom, immediate reversal at limits, invalid-range recovery and long-recording context. The DOM checks additionally cover batched input, fractional UI scale, scroll-proxy rounding, unchanged content duration and Follow projection. The focused tests in `tests/timeline.test.mjs` and `tests/timeline-workflows.test.mjs` exercise same-time capture, selection versus Load/Apply, snapshot time/pose, real scene recording, sampling/looping, switching and resuming takes, multi-selection, clipboard, duplicate, nudge, box selection, held-drag cancellation, pan/zoom/follow, context menus, frame ranges/deletion and direct toolbar access. They also check bounded DOM for 10,000 keys, Stop beside Record during export, fixed range/neighbor geometry as recorded timestamps pass 0, 9.999, 10 and 100 seconds, seek/view/key editing beyond the previous extent, unchanged pixel scale, stable Stop/Follow projection, complete long-time captions and bounded sample visits for 100,000-frame takes.

The actual-App matrix covers 32 configurations: 312/600/1000/1600 physical-pixel panel widths, English/Chinese, Light/Dark and 100/125% UI scale. It verifies one toolbar row without external overflow, persistent Follow, each complete numeric field's reachability, connected Follow cells, stable full numeric budgets, three fixed-height tracks, no empty Take footer and no label block below the third track. It also checks the last track remains reachable by scrolling and the native playhead paints before and after vertical scrolling. At 1250 logical pixels and above the complete default toolbar requires no horizontal scrolling.

Measurements are written to `../output/electron/verification/timeline-inline-layout.json`. Representative captures:

- `../output/electron/verification/timeline-inline-zh-light-1.25-1600.png` and `timeline-inline-zh-dark-1.25-1600.png`: complete direct toolbar and the three-track label boundary.
- `../output/electron/verification/timeline-inline-range-visible-en-light-1.25-312.png`: a complete range editor reached by horizontal scrolling while Follow stays visible.
- `../output/electron/verification/timeline-inline-controls-en-dark-1-600.png`: inline controls in a narrow production panel.

Browser captures validate frontend layout and interactions. Native Electron integration, packaged runtime and video decoding require the separate workspace/export acceptance checks; these focused results do not claim a completed final package verification.
